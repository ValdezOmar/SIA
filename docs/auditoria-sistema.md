# Monitor de auditoría del sistema

`sys_eventos_auditoria` es una bitácora técnica de solo registro. Su consulta está en **Sistema > Monitoreo > Auditoría**, con acceso exclusivo para roles `admin` y `super_admin`. La tabla ofrece búsqueda y filtros por tipo de evento, nivel, código HTTP y periodo. El detalle es de solo lectura y muestra los datos del cambio o la información técnica disponible. No se modifican otros Resources ni Relation Managers.

El listener Eloquent global registra altas, actualizaciones y eliminaciones de modelos con actor autenticado, clase/tabla/ID del registro, contexto HTTP y valores anteriores/nuevos. Se excluye la propia tabla de auditoría para evitar recursión. Campos que parezcan contraseñas, tokens, secretos, cookies o claves se almacenan como `[REDACTADO]`; valores de texto extensos se limitan.

El middleware global registra cada respuesta HTTP con código 400 o superior. Los códigos 400–499 se clasifican como advertencia y 500 o superior como crítico. El manejador de excepciones agrega su clase, línea y código HTTP, método, ruta, URL sin query string, usuario, IP y agente del navegador. En `datos.error_markdown` guarda el mensaje y la traza completa de la excepción y sus causas, incluidas consultas de errores SQL, para facilitar el diagnóstico. Antes de guardar redacta cookies, encabezados de autenticación y líneas que parecen contener contraseñas, tokens, secretos o claves. No registra cuerpos de solicitud/respuesta ni encabezados completos. Para errores 500 en navegación web se muestra una notificación genérica sin SQL ni traza; las excepciones de base de datos no se clasifican como rechazos operativos.

La migración `2026_10_20_150000_create_sys_eventos_auditoria_table.php` debe ejecutarse mediante el proceso normal de despliegue. La tabla debe contar con una política de retención acorde al volumen. Las operaciones masivas que no disparan eventos Eloquent (por ejemplo `Model::where(...)->update()` o SQL directo) no aparecen como cambios de modelo. Los eventos de cambios usan la misma conexión y transacción que la operación original, por lo que se revierten si la transacción de negocio se revierte. Si la escritura de auditoría falla, el sistema registra el problema en el log Laravel y deja continuar la operación original.
